# 订单一致性与可靠投递回归

## 补强内容

本次没有增加新的分布式锁或第二套消息机制，而是加固已有的数据库条件更新、唯一键、事务 Outbox 和消费者去重。

| 场景 | 已有保障 | 本次补强 |
| --- | --- | --- |
| 重复提交订单 | `(user_id, request_id)` 唯一键和原订单回查 | 保持原机制，并回归验证重复 key 不会创建第二笔订单 |
| 库存并发扣减 | `stock >= quantity` 条件更新 | 扣减/回补显式加入事务边界；库存记录缺失或扣减失败必须失败，不能静默成功 |
| 多实例 Outbox 扫描 | 消费端 eventId 去重 | 增加发送租约和每次投递的租约令牌；只有当前令牌可写回状态，过期租约可恢复且陈旧发送者不能覆盖新发送者 |
| Broker Nack/超时 | 指数退避重试 | 仅在 publisher confirm ACK 后标记已发送，并保存失败原因 |
| 消息不可路由 | mandatory return 原仅记录日志 | 检查 `CorrelationData.returned`，不可路由不标记已发送 |
| 通知消费失败 | Redis 7 天 eventId 去重 | 发布失败时删除刚取得的去重标记，使 RabbitMQ 重投可再次处理 |

Outbox 仍采用“至少一次”语义：进程在 broker ACK 后、数据库改状态前崩溃时会重发。通知消费者按 eventId 去重，因此重复比丢失更可接受；不要把它表述为“恰好一次”。

## 故障注入测试

新增单元测试覆盖：

- broker Nack：释放 Outbox 租约、记录错误、退避重试；
- 同一事件已被其他实例租约占用：本实例不得发送；
- 租约失效后被新实例接管：旧实例完成/失败写回必须带原令牌，不能覆盖新实例；
- broker ACK：才将 Outbox 标记为 sent；
- broker ACK 但路由失败（mandatory return）：不得标记为 sent，必须重试；
- Redis 发布失败：删除 eventId 去重标记并抛出，使消息重投；
- 库存条件扣减返回 0：订单失败，库存不能扣成负数；
- 取消回补时库存记录缺失：失败并由事务回滚。

## 运行

基础回归：

```powershell
.\tools\run-reliability-regression.ps1
```

集成回归会创建并删除一个随机 `sky_order_it_*` MySQL schema：

```powershell
.\tools\run-reliability-regression.ps1 -Integration
```

RabbitMQ 回归还会创建并删除随机 vhost，需先确认测试环境可安全执行：

```powershell
.\tools\run-reliability-regression.ps1 -Integration -Rabbit
```

本机缺少 Maven、MySQL、RabbitMQ 测试环境，因此未执行这些测试。执行前应备份或使用隔离数据库；不能在生产库执行集成回归。
