# 智餐外卖支付双链路

当前没有微信支付商户号：保留真实微信支付实现，本地用独立模拟路径验证订单业务。微信真实下单需要商户号及关联的小程序 AppID；没有商户配置不能完成真实扣款，不使用借来的商户凭据。接口要求参考 [微信支付 JSAPI/小程序下单文档](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)。

## 真实支付链路

用户提交订单 → 后端创建待支付订单 → 请求 `/user/order/payment` → 校验当前用户、订单状态与期限 → 从数据库读取实付金额 → 账户服务获取 OpenID → 微信 JSAPI 下单 → 返回 prepay_id → 商户私钥生成小程序支付签名 → 前端 `uni.requestPayment` 调起微信收银台 → 微信通知 `/notify/paySuccess` → 验签、验证平台证书与时间戳 → API v3 密钥解密 → 核对商户/AppID、币种、交易状态与订单金额 → 本地事务记录到账流水并更新订单 → Outbox/RabbitMQ 发布支付成功事件 → 通知服务提醒管理端。

- 支付请求只返回预支付参数，不能把它当成实际到账。
- 客户端收银台返回成功后，前端查询受保护的订单详情；确认 `payStatus=1` 且订单未关闭才显示成功。短时间未收到回调则进入详情页等待确认，不伪造成功，也不立刻再次扣款。
- 订单行锁、流水唯一约束和条件状态更新保证重复回调不会重复处理。
- 订单取消/超时后到账：保持取消并登记退款任务。退款任务用稳定退款号先查询、再申请，处理中继续查询，确认成功后才标记已退款。
- 购买红包使用独立购买订单，复用微信支付工具；验收到账后在事务中更新购买状态和发放资产。前端不再把收银台返回成功直接描述成红包已到账。

启用真实路径：`SKY_PAYMENT_MOCK_ENABLED=false`。同时提供商户、小程序、私钥、API v3 密钥、验签材料与 HTTPS 支付回调配置，具体参见 [支付配置与验收](payment-production-setup.md)。退款通过主动查单确认，退款回调地址可留空。正式环境使用 HTTPS/WSS、强认证密钥和 `prod` 配置，禁止模拟支付。缺少配置或微信请求失败不会自动回退成模拟成功。

## 本地模拟支付链路

用户提交订单 → 后端创建待支付订单 → 请求 `/user/order/payment` → 相同的用户归属、状态、期限检查 → 返回 `mockPayment=true` → 前端显示真实订单金额的本地支付确认框 → 用户确认 → 调用 `/user/order/payment/mock/confirm` → 后端再次检查开关、用户归属和订单状态 → 在共享订单事务中写入独立模拟交易流水 → 更新支付状态 → 后端订单详情确认已付款 → 前端进入成功页。

模拟支付不调用微信下单、不需要商户私钥或证书、不产生实际扣款。取消确认不会提交模拟到账；确认接口失败也不会显示成功。模拟路径不冒充经过微信验签的回调。

红包购买使用 `/user/red-packet/purchase-orders/payment` 和 `/user/red-packet/purchase-orders/payment/mock/confirm`，确认框金额取服务端购买订单的 `payAmount`，不写死金额。

本地配置：交易服务显式启动 `dev`，默认 `SKY_PAYMENT_MOCK_ENABLED=true`。需要切换时修改环境变量并重启交易服务。账户服务若也没有微信登录配置，可以单独启用已有的开发登录开关；开发登录与支付开关相互独立。前端不接受 URL 参数或本地开关强行指定支付模式，以后端返回的支付模式为准。

```powershell
$env:SPRING_PROFILES_ACTIVE = 'dev'
$env:SKY_PAYMENT_MOCK_ENABLED = 'true'
# 使用现有本地启动方式运行交易服务及其依赖，然后在 HBuilderX 重新运行小程序源码。
```

## 验收范围

2026-10-13：前端 27 项测试通过；本次选定的后端 14 项测试通过（其中生产配置保护 2 项、支付/订单/回调 12 项）。失败及错误均为 0。后端日志：`.runtime/payment-dual-chain.log`。小程序源码语法与支付交互已通过自动化验证，未声称已完成微信真机收银台联调。

本次测试覆盖真实路径使用数据库金额与 OpenID、返回微信签名参数而不提前标记支付成功、真实模式拒绝模拟确认、微信请求失败不回退、模拟路径不访问微信、两个模式都检查订单归属；前端验证真实收银台调用、本地确认、取消、确认失败、回调延迟和取消订单不显示成功。

真实路径的测试使用外部依赖替身验证代码行为，不能等同于商户真实联调。没有商户号时，真实扣款、微信外部回调和实际退款仍未验证。本地可以验证订单事务和幂等逻辑；涉及微信平台证书及签名的行为需单独测试，最终仍需合法商户配置联调。

## 面试回答约定

默认按真实支付源码讲解：微信 API v3/JSAPI、服务端金额与身份校验、RSA 签名、回调验签解密、流水幂等、订单状态机、异步退款和可靠通知。不主动展开本地模拟支付。

若明确问“是否真实上线、是否完成商户支付联调、是否有实际交易流水”，如实回答“真实链路代码已实现，但暂未配置商户号，尚未完成真实交易联调”，不把代码实现和真实交易验收混为一谈。
