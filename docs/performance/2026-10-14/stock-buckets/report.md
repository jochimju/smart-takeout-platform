# 2026-10-14：连接池、库存分桶与实际压测

结论：已完成本轮源码改造和正确性验证；**尚未达到或通过「每秒成功受理 800 个有效请求，并最终建成订单」的验收**。不得把 800 个入口请求（包含容量拒绝）写成 800 个成功订单。

## 实际实现

- 交易/商品 Feign 使用 `feign-hc5`，总池 512、每目标 256、租用等待 1s，关闭 HTTP 自动重试，增加连接池指标。真实 Feign 请求复用同一 HTTP 连接的测试通过。
- 交易/账户 Druid 明确配置初始/最小空闲 8、最大 32、等待 1s；HTTP 接入队列 1024、连接 4096、线程 256。运行指标确认这两项数据库池上限均为 32，池预算仍受 MySQL 全局资源限制。
- 新且尚未预热、没有历史预留的活动分成 8 桶；已初始化活动保留原账本。Redis Lua 原子扣总库存和选中桶库存；资格及请求去重仍按整个活动共享。
- 八条独立持久 MQ 队列，每桶一个消费者。兑现、失败恢复和取消按桶处理；MySQL 条件扣库存及全活动用户唯一索引继续兜底。取消回补原桶且只能归还一次；库存展示求桶剩余库存之和。
- 桥接使用独立锁保护跨实例重复交接，不锁库存；最多 200 条跨桶受理与 outbox 同事务持久化。Redis 受理记录核对改为 HMGET，逐项验证订单号和指纹。
- 终态最多 200 项 EVALSHA 流水线、独立调度器；部分成功或脚本丢失可幂等重放。只删除明确成功且状态仍匹配的事件。
- 领取消息明确限定九个合法创建路由并使用已有索引；READ_COMMITTED 避免领取范围间隙锁。事件删除改为参数表驱动主键点查。

普通下单入口及普通建单消费者沿用原链路；HTTP 池、数据库和消息表仍共享，不能保证普通下单性能不受影响。普通回归测试发现原支付补偿 INSERT SELECT 的 `id=id` 歧义，本轮仅修正该表达式并通过取消/退款状态回归；没有进行真实商户支付。

## 正确性测试

最终目标套件共 111 项，**107 项执行通过，4 项条件测试跳过**（额外 Rabbit/完整 15 分钟条件）。包括真实 MySQL 的独立桶锁、200 项事件删除不锁不相关行、更新取消状态不被旧完成删除、跨桶用户唯一性及回滚；真实 Redis 的扣库存、全活动去重、精确大 Long、原桶补偿、流水线部分失败与 NOSCRIPT 重放；普通订单回归及 Feign 实际连接复用。

测试从固定源码快照构建，避免共享工作区 target 被其它构建清理。正式默认保留 **8 单**批次；最大支持 16 单，16 单试验未通过有效容量验收，不据此改变默认值。最新运行包使用外部配置试验 16 单；最终源码默认值和该试验配置须区分。

全量未筛选测试首次碰到既有 WeChatPaymentProtocolTest 的 Base64 错误；该协议测试不属于本轮目标套件，不能将目标套件通过表述为整个仓库所有测试通过。

## 测试方法和边界

本机 Windows、20 个逻辑 CPU、约 32 GiB 内存；压测器和服务仍在同一台电脑。MySQL/RabbitMQ 使用专用 schema/vhost，Redis 16380 专用进程；服务端口 18081/18082/18083。直接测试交易接口，未经过生产网关。有效用户和地址为专用造数，单活动、库存 60000、用户按连续 ID 均匀分桶，不使用红包，不执行支付。

计划 800 秒杀请求/秒 + 5 普通下单请求/秒，持续 60 秒；配额 500，建单期限 120 秒。前端按原机制轮询真实订单。计数同时检查提前拒绝、漏发、未知响应及普通订单。每个阶段的源码/配置/生成器参数存在变化，表格是诊断记录，**不能作为只有一个变量变化的 A/B 因果比较**。

更换生成器指标标签去掉请求 ID 的高基数，避免约 20 万条时序记录。不同轮次预分配 VU 也有变化。部分实验发生磁盘空间不足、TCP 连接拒绝或漏发；均不作为达标证据。只清理已停止、已归档且属于本任务的测试数据及重复包，未清理业务数据或更改 MySQL 全局持久化参数。

## 已确认的优化依据及仍未解决的验收

旧事件删除在 500 条隔离数据上的 EXPLAIN 为 ALL 整表扫描；参数表 JOIN 后为 PRIMARY 的 eq_ref 点查。实际 jdbc_delete 平均耗时从上一诊断轮约 126ms 到下一轮约 34.5ms；其它变量/负载也变化，不能将差异全部归因于该 SQL。跨桶写门控等待在诊断轮接近 0，但单独这一项不能证明全链路能达到 800。

剩余验收必须先获得没有漏发、没有接入异常的负载，再按最终配置复测；当前同机测试没有排除生成器、系统后台进程、HTTP 接入及账户鉴权调用的影响。数据库池上限设置为 32 只验证了配置生效，尚未证明消除了所有资源等待。不能把这一轮失败归咎为已证实的单一硬件或业务瓶颈。

多活动并发、用户 ID 哈希倾斜、使用红包、真实网关、持续更长时间、Redis 故障转移、真实支付尚未完成验收。一人一单沿用一份有效资格语义，取消可重新抢购。没有同环境同步下单对照组，**350ms→65ms、吞吐提升 3 倍也未验证**。

新增迁移 V2026101403 只在隔离/随机测试库执行；业务库未迁移、业务服务未重启。旧交易实例必须停止、旧积压核对后才能上线新分桶活动，禁止旧桥接与新分桶活动混跑。

原始 JSON、Prometheus、执行计划、冻结快照和最终测试日志保存在本目录；未复制令牌、含密码配置或用户真实业务数据。
