# 小程序本地开发环境

## 运行方式

本地开发使用独立模拟支付链路，无需微信支付商户号。真实支付实现保留，只有配置合法商户参数后才能进行真实交易联调。

1. 启动 MySQL、Redis、RabbitMQ。
2. 启动 `sky-take-out-jjs` 的账户、商品、交易、网关及通知服务和服务发现等现有依赖；显式使用 `dev` 配置。小程序通过网关访问 `http://127.0.0.1:8080`。
3. 使用 HBuilderX 导入本目录，运行到“微信开发者工具”。
4. 微信开发者工具实际打开的编译目录应为：
   `unpackage/dist/dev/mp-weixin`
5. 在微信开发者工具的本地设置中勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。

## 本地接口地址

小程序接口根地址配置在 `utils/env.js`，开发者工具模拟器使用：

```js
export const baseUrl = 'http://127.0.0.1:8080'
```

`127.0.0.1` 仅适用于电脑上的微信开发者工具模拟器。手机里的 `127.0.0.1` 指手机自身，不能访问电脑后端；如果以后需要真机调试，应改用电脑局域网 IPv4 地址，并放行对应端口。

## 本地模拟能力

为避免依赖线上微信配置，本项目开发环境应使用：

- 模拟微信登录：账户服务开启开发登录开关后，根据配置的固定 OpenID 查询或创建测试用户，不调用真实微信登录接口。
- 模拟支付：交易服务在 `dev` 下默认启用 `SKY_PAYMENT_MOCK_ENABLED=true`；前端显示订单实际金额，用户确认后调用专用确认接口，后端更新订单，前端查询确认已付款后再显示成功。不调用微信商户平台，不产生真实扣款。

这两项只允许在 `dev` 配置中启用，不能混入正式环境逻辑。

真实模式使用 `SKY_PAYMENT_MOCK_ENABLED=false`，普通订单会调起微信收银台，并等待服务端回调确认到账。没有商户参数时此模式不能完成真实交易，也不会自动切回模拟成功。修改配置后重启交易服务，修改小程序源码后在 HBuilderX 重新运行，不能只刷新旧的编译目录。

完整两条链路见 [支付双链路说明](../sky-take-out-jjs/docs/payment-dual-chain.md)。

## 源代码基线

- 保留旧 `master` 分支不动。
- 多餐厅功能在 `feature/multi-restaurant` 分支开发。
- 该分支从 `origin/updateV2.0` 创建，比旧 `master` 更接近当前后端接口。

## 尚需注意

当前仓库中的微信 AppID 与后端配置并不一致，因此不能把真实微信登录是否成功作为本地环境成立的前提。后续实现本地模拟登录后，开发者工具可以独立完成六餐厅、菜品、购物车、下单和模拟支付流程。
